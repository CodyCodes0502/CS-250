# CS-250

    How do I interpret user needs and implement them into a program? How does creating “user stories” help with this?

  Creating user stories helps to break down the user needs into easy to process and handle tasks to be completed by the development team. By listening to the client and breaking up their needs into small easy to handle stories, it gives a clear checklist of components to be completed for the project. 
  
    How do I approach developing programs? What Agile processes do I hope to incorporate into my future development work?

  When developing programs, I start by doing a bit of planning. Making a UML diagram as well as writing down some basic pseudocode. Once that is complete I can start coding up the actual program itself. In the future I would like to implement user stories more into the planning process. I think this will be helpful for me now that I am starting to code bigger and more advanced projects than the basic applications I have been using to learn, in that it will help me break down the bigger project into smaller parts that are less intimidating. 
  
    What does it mean to be a good team member in software development?

  A good team member in a software development team is one that is self motivated and a good communicator. Clear communication is key not only while in meetings with the team and discussing the project, but also in writing the code itself, as leaving clear comments in your code can greatly help other team members add onto or debug your code.
